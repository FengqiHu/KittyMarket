# 首页热门商品推荐

首页只有一个热门商品列表，覆盖所有 `state = 0` 商品，先排序再通过数据库分页。每页 8 件，支持分类、页码及跳转；有库存的商品排在售罄商品前，同分按商品编号倒序。

## 排序信号

- 游客、卖家及没有个人资料的买家使用销量、收藏人气作为基础排序。
- 买家浏览详情时，`MLproduct_view` 保存每个账号、商品的访问次数及最近访问时间。30 秒内重复访问不重复计数；只使用最近 90 天记录，并按时间衰减。
- 有效购买（`orderstate > 0`）和收藏构成个人偏好；购买通过 `buyername` 匹配账号，订单的 `owner` 是卖家。
- 浏览、购买、收藏同时提高相关商品、同大类及同子类的排序。默认子类不参与子类偏好。
- 猫咪档案按年龄、体重范围、品种及生长状态匹配，生长状态与商品名称、描述中的相关词匹配。多猫家庭取最佳匹配；缺失或格式错误的适用范围不加分，明确不匹配的范围降分。
- 个性化排序按当前服务端会话计算，不接受客户端指定用户，也不使用共享的热门商品缓存。

具体权重位于 `RecommendationRepository`。这是基于现有数据的规则评分；浏览记录从启用此功能后开始积累。页面刷新、返回首页或翻页时会重新计算，行为或库存变化可能改变顺序。

## 验证

`RecommendationIntegrationTests` 使用真实 MySQL、独立测试数据与事务回滚，覆盖全部商品跨页完整性、冷启动、浏览偏好与账号隔离、过期记录、购买及取消订单、收藏、猫咪适配、多猫和生长状态。

2026-10-18 验证：7 项推荐集成测试及 14 项相关回归测试通过；前端 lint 和生产构建通过。本地 API 的 5,026 件商品共 629 页，第 2 页和最后一页读取正常。
