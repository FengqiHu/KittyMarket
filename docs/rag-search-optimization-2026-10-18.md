# RAG 商品检索提速

## 改动

- 商品搜索停止调用对话模型生成已从前端移除的说明；保留语义检索、商品编号及全部结果分页。猫咪选粮说明仍可使用对话模型。
- 查询向量缓存最多 256 条，完整排序缓存最多 128 条，均保留 10 分钟；相同查询的并发请求合并，翻页和分类筛选复用同一完整排序。
- 排序缓存只保存商品编号。每次请求仍读取当前数据库商品，价格、库存、分类及上架状态不从旧缓存取值；商品文档变化通过目录哈希使旧排序失效。
- 商品向量以 float32 二进制保存到 MySQL `rag_product_embedding`，按接口地址、向量模型命名空间及商品文档哈希核对复用；不保存 API Key。改动商品只计算改动部分，价格及正库存数量变化不重新向量化。
- 初次缺失向量按每批最多 10 件、默认 4 个并发请求处理；每批完成后保存，可复用失败之前已完成的部分；建索引遇到超时或限流时对该批次最多重试 2 次。通过 `RAG_INDEX_CONCURRENCY` 配置并发数，限制为 1～8。

## 验证

31 项相关测试通过，覆盖跨页完整性、缓存查询合并、过期与失败重试、模型隔离、重启复用、单件商品增量计算、实时价格与库存，以及 MySQL 二进制向量写入和读取。新增原生接口测试验证文本独立向量请求格式、按返回索引还原顺序、异常返回校验与限流/超时处理。测试使用模拟模型或独立事务数据，不调用真实 Qwen。

实测环境为本地 Docker Compose、5,026 件商品、`text-embedding-v4`，所有真实性能测试均校验返回 `mode=rag`。优化前使用已有内存索引，同一查询第 1 页耗时 4.215 秒，第 2 页耗时 3.954 秒；两次均重复生成不显示的检索说明。

优化后，通过前端 `/api` 代理请求实测：

| 场景 | 优化前（秒） | 优化后（秒） |
| --- | ---: | ---: |
| 相同查询第 1 页 | 4.215 | 0.053～0.298 |
| 相同查询第 2 页 | 3.954 | 0.207 |
| 相同查询第 3 页 | 未测 | 0.197 |
| 新的语义查询 | 未测 | 0.427 |

这是本机少量请求的实测值，不代表高并发容量或外部 Qwen 的延迟保证。所有优化后响应均为 `mode=rag`、每页 8 件、总数 5,026，且 `summary` 为空。

首次迁移时遇到一次外部请求超时，已保存的 1,890 件向量成功在后端重建后复用；随后只计算缺失的 3,136 件，补齐耗时约 67.8 秒。完整向量已持久化，后续重启不需要再调用模型全量向量化。

## 重启与额度状态

再次重建后端容器后，日志确认装载 5,026 件持久化商品向量，重用 5,026 件，新增向量化 0 件。随后远端查询向量请求被百炼以 `AllocationQuota.FreeTierOnly` 拒绝，提示免费额度用尽且启用仅免费模式；这一轮响应回退为 `keyword`，因此没有计入 RAG 提速数据。

商品向量持久化不等同于离线语义检索：新的查询仍需要调用向量模型。查询向量和排序的 10 分钟缓存位于进程内，重启后清空。

## 切换模型

按用户指定，将本机 `.env` 中的 `QWEN_EMBEDDING_MODEL` 改为 `tongyi-embedding-vision-plus-2026-03-06`，并增加 DashScope 原生多模态向量接口适配。该模型的 OpenAI 兼容接口实际返回 `model_not_supported`，原生接口连通性测试返回 HTTP 200、每段文本 1152 维。

商品和查询均只发送文本，每个 `input.contents` 元素生成独立向量，并按响应中的 `index` 对回原文顺序。继续使用每批 10 件、4 个并发的限制。模型命名空间隔离旧向量，保留原模型已保存的数据；首次切换需计算新模型向量。

## 修复搜索把全目录作为命中结果

前述提速版本缓存了全目录的相似度排序，但没有过滤弱相关商品，导致不同查询的 `total` 都是 5,026。修复后缓存商品编号及分数，搜索仅保留分数不低于 `max(0.85, 最高分 - 0.03)` 的结果，再应用分类、分页；不设置固定前 N 件上限。分数为 LangChain4j 的 `(余弦相似度 + 1) / 2`。

门槛使用当前模型和已保存的 5,026 件商品向量校准：手机、量子计算教材、随机字符串的最高余弦相似度均低于 0.7（对应分数 0.85）；相关商品词通过绝对门槛后，再去除与首项分差较大的弱相关尾部。可通过 `RAG_SEARCH_MIN_SCORE`、`RAG_SEARCH_SCORE_WINDOW` 调整，两者范围均为 0～1。该启发式筛选不等同于人工标注的准确率评估，换模型后需重新校准。

成功语义检索没有命中时返回空列表，保持 `mode=rag`，不再用关键词结果填充；只有模型调用失败才回退关键词检索。空查询仍展示全部在售商品。猫咪档案推荐保留原有适用条件与排序，不使用商品搜索门槛。

本轮 19 项相关测试通过，新增覆盖：同义词语义命中、21 件相关商品跨页完整性、无关商品排除、弱相关尾部过滤、无命中保持空结果、分类不扩张命中范围，以及猫咪推荐行为不受搜索门槛影响。
