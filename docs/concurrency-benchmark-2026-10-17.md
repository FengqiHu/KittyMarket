# 本机商品检索并发压测（2026-10-17）

测试目标：`GET /good/rag-search?query=幼猫鸡肉&kind=猫咪主粮`，本机 Spring Boot 8080 端口，数据库商品列表 5026 条。当前未配置 Qwen API Key，接口返回 `keyword` 模式；RabbitMQ 已启用。脚本从同一台机器发出只读请求，使用 HTTP 长连接，校验 HTTP 200 和响应中的 `page=success`。

判定条件：错误率不超过 1%，P95 响应时间不超过 1000 毫秒，每个并发工作线程至少完成 2 次请求。每档若重复测试，则所有轮次都必须通过。

| 并发请求 | 每轮时长 | P95 响应时间 | 错误 | 结论 |
| ---: | ---: | --- | ---: | --- |
| 128 | 10 秒 | 742 毫秒 | 0 | 通过 |
| 160 | 10 秒 × 2 | 945 / 929 毫秒 | 0 / 0 | 两轮通过 |
| 168 | 10 秒 × 2 | 1133 / 788 毫秒 | 0 / 0 | 一轮超时延阈值 |
| 176 | 10 秒 × 2 | 1169 / 852 毫秒 | 0 / 0 | 一轮超时延阈值 |
| 192 | 10 秒 × 2 | 1332 / 925 毫秒 | 0 / 0 | 一轮超时延阈值 |
| 216 | 4 秒 | 972 毫秒 | 0 | 单轮通过，不能视为稳定上限 |
| 256 | 4 秒 | 1656 毫秒 | 0 | 未通过 |

**保守结论：在上述条件下，已验证可稳定承受 160 个同时进行的商品检索请求。** 168 并发开始出现 P95 超过 1 秒的轮次，因此当前数据不足以给出精确的物理极限。高并发档位吞吐量大致为每秒 240～265 次请求。数字会随机器、数据库、商品数量、查询词、网络和运行中的其他任务变化。

复现边界测试：

```sh
python3 scripts/benchmark_concurrency.py --start-concurrency 160 --max-concurrency 192 --duration 10 --repeats 2 --json-out /tmp/kittymarket-concurrency.json
```

这项测试衡量的是无 Qwen Key 时的商品检索读取能力；它不包含猫咪推荐、商品写入、RabbitMQ 索引更新或 Qwen 远程调用的容量。启用 Qwen 后应分别重新压测相关接口。
